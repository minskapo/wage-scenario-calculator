# 시나리오 탭 재설계 · 현황 탭 연 임금 표시 — 설계 문서

- 작성일: 2026-07-29
- 배경: 배포 후 실제 사용해보니 시나리오 탭의 "여러 시나리오 카드 + 별도 비교표" 구조가 어렵다는 피드백. 한 번에 하나의 인상안만 표 안에서 바로바로 계산해보는 단순한 형태로 재설계한다. 동시에 현황/시나리오 탭에 연 임금 표시를 추가하고, 시나리오 탭에서 가상의 직급을 추가해볼 수 있게 한다.

## 1. 범위

- `js/ui/status-tab.js`: 연 임금 표시 추가 (계산 로직 변경 없음)
- `js/ui/scenario-tab.js`: 전면 재작성 — 다중 시나리오 비교 구조를 단일 라이브 표로 교체
- `js/main.js`: `renderScenarioTab` 호출부 단순화 (`getSelectedGrade` 제거)

`js/calc/net-pay.js`, `js/calc/scenario.js`, `js/data/*`, 현황 탭의 부양가족 입력/공제내역 표시, 추이/참고정보 탭은 변경하지 않는다.

## 2. 현황 탭 — 연 임금 표시

- 요약 카드에 "연 임금(연 총 급여)" 항목을 1개 추가한다. 값은 선택된 직급의 `netPayResult.totalWage × 12`.
- 전체 직급표에 "연 임금" 컬럼을 "임금 총액" 컬럼 바로 옆에 추가한다. 각 행은 `row.netPayResult.totalWage × 12`.
- 연 실수령액(세후)은 표시하지 않는다 — 연 총 급여(세전)만 보여준다.
- 계산 로직 변경 없음. 순수 표시용 파생값(×12)이다.

## 3. 시나리오 탭 재설계

### 3.1 제거되는 기능 (기존 구현 대비)

- 여러 시나리오 동시 비교, 시나리오 이름 입력, 시나리오 카드, 복제 버튼
- 시나리오별 "새 임금항목 추가" (가상 직급 추가로 대체, 성격이 다름)
- 시나리오 간 공제 내역 비교표 — 시나리오가 하나뿐이므로 비교 대상이 없어짐
- 현황 탭의 "선택 직급" 강조와의 연동(`getSelectedGrade` 의존성) — 이제 모든 직급이 표에 항상 다 보이므로 불필요

### 3.2 유지되는 것

- 부양가족 수 연동(`getDependents()`, 현황 탭에서 설정한 값을 그대로 읽음)
- 이미지 내보내기(`attachExportButton`), 실수령액 계산(`calculateNetPay`), 인상 적용(`applyAdjustments`) — 모두 기존 함수 재사용, 신규 계산 로직 없음
- 하단 안내 문구(부양가족 N인 기준, 간이 추정치 안내)

### 3.3 상단 — 전체 일괄 적용

- `인상액(원)` 입력칸 1개 + `인상률(%)` 입력칸 1개. 두 칸 사이에 자동 변환 관계는 없다(각 행 기준값이 다르므로 상단에서는 서로 계산할 수 없음).
- 인상액 입력 → 모든 행(가상 직급 포함)의 인상액을 동일한 원 금액으로 채운다. 각 행의 인상률(%)은 그 행의 현재 기본급 기준으로 각자 계산된다.
- 인상률 입력 → 모든 행의 인상률을 동일한 %로 채운다. 각 행의 인상액은 그 행의 현재 기본급 기준으로 각자 계산된다.
- 일괄 적용 이후에도 각 행에서 개별적으로 값을 덮어쓸 수 있다.

### 3.4 표 컬럼 구성

직급 1개 = 1행. 실제 직급(현재 `wageTable`의 8개 행) + 세션 중 추가한 가상 직급.

| 컬럼 | 내용 |
|---|---|
| 직급 | 직급명. 가상 직급 행에는 삭제 버튼 포함 |
| 현재 월 기본급 | `items`에서 `기본급` 항목의 금액 |
| 현재 월 실수령액 | `calculateNetPay(items, dependents, taxRules).netPay` |
| 현재 연 임금 | `calculateNetPay(...).totalWage × 12` |
| 인상액(원) | 입력 필드. 정수 원 단위 |
| 인상률(%) | 입력 필드. 소수 1자리까지 |
| 인상 후 월 기본급 | `applyAdjustments(items, [{itemName:'기본급', type:'fixed', value: 인상액}])`으로 계산 |
| 인상 후 월 실수령액 | 인상 후 items로 `calculateNetPay` 재계산 |
| 인상 후 연 임금 | 인상 후 `totalWage × 12` |
| 실수령액 인상률 | `(인상후netPay - 현재netPay) / 현재netPay × 100`, 소수 1자리, 분모 0이면 '-' |

**행 내부 인상액↔인상률 자동 변환** (일괄 적용과 달리, 행 안에서는 그 행의 현재 기본급을 기준으로 서로 계산 가능):
- 인상액 입력 시 → 인상률 = `round(인상액 / 현재기본급 × 100, 1)`을 인상률 칸에 채움
- 인상률 입력 시 → 인상액 = `round(현재기본급 × 인상률 / 100)`을 인상액 칸에 채움
- 무한 루프 방지: 프로그래밍적으로 값을 채울 때는 `input` 이벤트를 재발생시키지 않고, 계산된 값만 DOM에 직접 대입한다.

### 3.5 렌더링 전략 — 라이브 갱신과 포커스 유지

- 초기 렌더링, 가상 직급 추가/삭제, 전체 일괄 적용은 표 전체(또는 해당 부분)를 다시 그린다.
- 개별 행의 인상액/인상률 입력(타이핑 중)은 표 전체를 다시 그리지 않는다. 대신 해당 행의 "인상 후" 4개 셀(월 기본급/월 실수령액/연 임금/인상률)만 `textContent`를 직접 갱신한다. 입력 필드 자체는 다시 그리지 않으므로 포커스와 커서 위치가 유지된다.
- 탭 전환 시(현황 탭에서 부양가족 수가 바뀌었을 수 있음) `refresh()` 함수를 노출해 모든 행의 "현재"·"인상 후" 값을 최신 `getDependents()` 기준으로 다시 계산한다. `js/main.js`의 탭 클릭 리스너가 시나리오 탭으로 전환될 때 이 함수를 호출한다(기존 `refreshComparison`과 동일한 훅 지점, 이름만 유지 또는 `refresh`로 변경).

### 3.6 가상 직급 추가

- "+ 가상 직급 추가" 버튼 → 인라인 입력 폼(직급명 텍스트 입력 + 월 기본급 숫자 입력 + 추가 버튼)이 표 아래에 나타난다(기존 시나리오 탭의 "새 항목 추가" 폼과 동일한 인라인 패턴, `window.prompt` 사용 안 함).
- 가상 직급의 `items`는 `[{ name: '기본급', amount, taxable: true }]` 하나뿐이다(직책수당 없음).
- 가상 직급은 이 세션(페이지를 새로고침하기 전)에서만 유지되며 `js/data/wage-table.js`에는 저장되지 않는다.
- 가상 직급 행에는 개별 삭제 버튼이 있다.
- 직급명이 비어 있거나 기존 행(실제 직급 또는 이미 추가한 가상 직급)과 이름이 겹치면 인라인 오류 메시지를 보여주고 추가하지 않는다(기존 "새 항목 추가"의 중복 검증 패턴 재사용).

## 4. 데이터/인터페이스 변경

- `renderScenarioTab(container, { wageTable, taxRules, getDependents })` — `getSelectedGrade` 파라미터 제거. 반환값은 `{ refresh: () => void }` (기존 `refreshComparison`에서 이름 변경).
- `js/main.js`: `renderScenarioTab` 호출부에서 `getSelectedGrade: statusApi.getSelectedGrade` 줄을 삭제하고, 탭 클릭 리스너의 `scenarioApi.refreshComparison()` 호출을 `scenarioApi.refresh()`로 변경한다.
- `js/ui/status-tab.js`의 `renderStatusTab` 반환 인터페이스(`getSelectedGrade`, `getDependents`)는 변경하지 않는다 — 시나리오 탭이 안 쓸 뿐, 다른 소비자가 생길 가능성을 고려해 그대로 둔다.
- `js/calc/net-pay.js`, `js/calc/scenario.js`는 변경 없음.

## 5. 테스트

- `js/calc/scenario.js`(`applyAdjustments`)와 `js/calc/net-pay.js`(`calculateNetPay`)는 이미 테스트가 있고 이번 변경으로 로직이 바뀌지 않으므로 기존 13개 테스트는 그대로 통과해야 한다.
- 이 재설계는 DOM 렌더링/이벤트 바인딩 위주라 자동화 테스트 대상이 아니다(기존 UI 태스크들과 동일한 패턴) — `node --check` 문법 검증과 로컬 정적 서버 구조 확인으로 검증한다.

## 6. 열린 항목 (구현 단계에서 유의)

- 인상액↔인상률 자동 변환 시 반올림 오차로 왕복 변환이 완벽히 일치하지 않을 수 있음(예: 인상률 입력 → 인상액 계산 → 다시 인상률로 역산하면 소수점 차이 발생 가능). 사용자가 마지막으로 입력한 칸의 값을 "원본"으로 취급하고, 반대편 칸은 항상 그 값에서 파생된 표시값으로 취급한다.
